# MoonHawlk.github.io

Personal portfolio website for Filipe Moreno, a data scientist working with LLMs, NLP, RAG and GenAI. It also hosts other projects of mine as embedded sites.

**Live at:** [moonhawlk.github.io](https://moonhawlk.github.io)

---

## Stack

Plain HTML, CSS and vanilla JavaScript, served by GitHub Pages. No framework and no dependencies beyond Google Fonts. A small Python script (standard library only) generates the project and post pages.

```
├── content/                 # Everything you edit to change the site

│   └── writing/*.md         # Posts
├── projects/                # Generated by tools/build.py, do not edit by hand
├── writing/                 # Generated by tools/build.py, do not edit by hand
├── constellation_watches/   # Embedded site, generated by tools/sync_embeds.py
├── tools/

└── design/                  # DESIGN_SYSTEM.md, LinkedIn banner, preview image source
```

The rule of thumb: edit `content/`, run `python3 tools/build.py`, commit everything it changed.

## Build

```bash
python3 tools/build.py
```

It does three things:

- builds a page for every enabled project in `content/projects.json`, plus the `/projects/` list;
- builds a page for every published post in `content/writing/`, plus `writing/posts.json`, which the home page reads;
- adds `?v=<hash>` to every CSS and JS link (also in `index.html` and `404.html`), so visitors get the new file as soon as it changes.

Run it after changing anything in `content/`, `assets/css/` or `assets/js/`. Only pages it generated itself are ever removed, so folders you create by hand are safe.

## Site Info (`content/site.json`)

Details that show up in several places live in one file: name, initials, role, current company, location, email, LinkedIn, GitHub, site URL, page title, description and copyright.

```json
{
    "company": "SiDi",
    "copyright": "© {year} {name}"
}
```

- A value can use another one inside braces, such as `{name}` or `{company}`. `{year}` is always the current year.
- On the home page, an element marked `data-site="company"` shows that value, `data-site-href="email"` sets a link, and `data-site-content="description"` sets a meta tag. To use a value somewhere new, add the attribute to the element.
- Generated pages read the name, initials and copyright when they are built, so run the build after changing those.
- Link previews on LinkedIn, WhatsApp and similar apps do not run JavaScript, so they show the text written in the `<head>` of `index.html`. That text avoids details that change, such as the company.

## Writing

Each post is a Markdown file in `content/writing/`, named `YYYY-MM-DD-slug.md`. It is published at `/writing/<slug>/`.

```markdown
---
title: Why RAG is not a silver bullet
date: 2025-03-01
summary: One or two sentences shown on the home page card.
draft: true
---

The post itself, in Markdown: headings (##), paragraphs, **bold**, *italics*,
[links](https://example.com), `code`, lists, > quotes and fenced code blocks.
```

- Remove `draft: true` (or set it to `false`) to publish the post, then run the build.
- The Writing section and its menu link only appear on the home page when at least one post is published.
- The three posts already in the folder are drafts with a title and summary, waiting to be written.

## Project Pages

Every public repository listed in `content/projects.json` gets its own page at `/projects/<repo>/`, and the full list lives at `/projects/`.

### Add a project

Add an entry to `content/projects.json`:

```json
{
  "slug": "repo-name",
  "name": "Display name",
  "description": "One or two sentences shown on the card and the page.",
  "repo": "https://github.com/MoonHawlk/repo-name",
  "homepage": null,
  "language": "Python",
  "tags": ["LLM", "RAG"],
  "updated": "2026-10-04",
  "enabled": true
}
```

- `slug` must match the GitHub repository name, since it is also the folder name.
- `homepage` is optional. When set, the page shows a "Live demo" button.
- `image` and `image_alt` are optional. Point `image` at a file in the repository's raw URL (for example `https://raw.githubusercontent.com/MoonHawlk/repo-name/main/docs/screenshot.png`), so no image is copied into this site.
- `updated` is shown on the page as "Last update" and sets the order on `/projects/`, newest first.

### Turn a project off

Set `"enabled": false` and run the build. It removes that project's page and hides it from `/projects/`.

### Search and filters

On `/projects/`, the search box matches names, descriptions, tags and languages, and it tolerates partial or misspelled input (for example `lmm` finds `LLM`). The tag chips appear for every tag shared by at least two projects, and selecting several chips narrows the list to projects that have all of them.

## Embedded Sites

Other projects of mine are published inside this site as plain folders, each served by GitHub Pages at `/<folder>/`. Their source stays in their own repositories; `tools/sync_embeds.py` copies them in.

| Folder | Source repository | Live at |
|---|---|---|
| `constellation_watches/` | [constallation_watches_store](https://github.com/MoonHawlk/constallation_watches_store) | [moonhawlk.github.io/constellation_watches/](https://moonhawlk.github.io/constellation_watches/) |

When it copies a repository, the script:

- leaves out files that only matter to the original repository, such as its hosting setup (`.htaccess`, `DEPLOY.md`), its dev docs (`README.md`, `CLAUDE.md`) and the `.github/` folder;
- removes every comment from the HTML, CSS, JS and SVG files, without changing any code;
- stops with an error if a forbidden word (for the store: Hostinger, hPanel, FTP deploy) is still present;
- writes `.embed-source` in the folder with the repository and commit it was copied from.

The original repositories are never modified, so the store keeps its own deploy.

### Update an embedded site

Copies do not follow the original repository on their own. After pushing to the store, run:

```bash
python tools/sync_embeds.py constellation_watches
git add constellation_watches
git commit -m "Update Constellation Watches store"
git push
```

Run it without arguments to update every embedded site. Do not edit these folders by hand, since the next sync replaces them.

### Add an embedded site

Add an entry to `EMBEDS` at the top of `tools/sync_embeds.py` with the folder name, repository URL, branch, the files to leave out and, optionally, words that must not appear. Then run the script. The site must use relative paths (`style.css`, not `/style.css`) to work inside a folder.

## Link Preview Image

`assets/img/og-image.png` (1200 × 630) is what LinkedIn, WhatsApp and others show when the site is shared. Its source is `design/og-image.html`. After editing it, export a new PNG with Chrome:

```bash
chrome --headless=new --hide-scrollbars --window-size=1200,630 --virtual-time-budget=6000 \
  --screenshot=assets/img/og-image.png design/og-image.html
```

LinkedIn caches previews; use the [Post Inspector](https://www.linkedin.com/post-inspector/) to refresh it.

## Running Locally

The pages load `content/site.json` and `writing/posts.json` with `fetch()`, so open the site through a local server, not straight from the file:

```bash
python -m http.server 8080
```

Then open [http://localhost:8080](http://localhost:8080). The local server shows its own error page instead of `404.html`; open `/404.html` directly to see it.

## Repository Notes

- `.nojekyll` turns off Jekyll on GitHub Pages, so files are served exactly as they are in the repository.
- `design/references/` holds the reference paintings behind the palette. It is ignored by Git.
- `.mailmap` groups the older commit identities under one name in `git log` and `git shortlog`.
